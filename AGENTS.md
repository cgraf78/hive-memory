# AGENTS.md

## About

`hive-memory` is vendor-neutral durable memory for AI agents; the CLI
is `hm`. Canonical data is files on disk; indexes and caches are
rebuildable. [SPEC.md](SPEC.md) is normative for v1 behavior;
[PLAN.md](PLAN.md) is design rationale.

## Layout

- `src/lib.rs` owns reusable policy and data handling; `src/main.rs`
  and `src/cli/` are the CLI adapter (parsing, dispatch, output, exit
  status). `src/README.md` lists module ownership: persist vocabulary in
  the module that owns the stored schema, never retyped at call sites.
- `tests/*.rs` are Cargo integration tests; `tests/shell/` holds the
  shell-owned install and release tests.
- `examples/config*.toml` are compiled into `src/config.rs` tests via
  `include_str!`, so they must stay valid. `man/man1/hm.1` ships in
  release archives.

## Invariants

- Writes are append-only; newer facts hide stale ones via supersession
  at query time, and nothing is hard-deleted.
- Indexes are a recall optimization only. Store, scope, project,
  audience, and validity are mandatory post-filters.
- Secret-looking content is refused on write. Report detector IDs only;
  never echo matched secret text.
- Capture/reconcile must not silently change agent-visible memory.
- The dependency tree stays pure Rust: a C-linking crate breaks the
  static musl release build (why tantivy's default features are off).
- Behavior, file-format, or hook-contract changes need a SPEC.md
  update. README performance numbers come from the `perf_budget` test.

## Testing

CI runs these through the shared `cgraf78/actions` workflows:

```sh
cargo fmt --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo build --release --locked
RUSTDOCFLAGS='-D missing-docs' cargo doc --locked --no-deps
cargo test --locked
cargo audit --file Cargo.lock
tests/shell/install-test; tests/shell/release-scripts-test; tests/shell/automation-test
HIVE_MEMORY_PERF_BUDGET_MULTIPLIER=4 cargo test --release --locked --test perf_budget -- --ignored --nocapture --test-threads=1
cargo test --locked --test cloud_sync_sim -- --ignored --nocapture
```

- `[lints.rust] warnings = "deny"`; edition 2024; no MSRV job. Drop the
  perf multiplier locally to apply the stricter budget.
- CI also smoke-tests a packaged musl archive (`scripts/package-release.sh`,
  `scripts/smoke-release.sh`), runs `cargo install --path . --locked`,
  and runs `scripts/termux-ci.sh` in an Android emulator.

## Test isolation

- Spawn `hm` only through `common::hermetic_hm()` (`tests/common/mod.rs`):
  it scrubs inherited `HIVE_MEMORY_*` and `GIT_*` and sandboxes every
  XDG base dir. `clippy.toml` bans the raw `assert_cmd` `cargo_bin*`
  helpers, so bypassing it fails clippy.
- Never touch a real `hm` store, project state, or cloud credentials.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale
  rows; local tests do not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`.
- `install.sh` is generated by cgraf78/actions release-installer and
  byte-checked by `actions-sync`; never edit it here.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh <this checkout>` run from
  cgraf78/actions at the locked SHA.
- Vendored release scripts (see `scripts/.release-scripts.manifest`):
  `scripts/{release,release-lib,release-tag,release-version,package-release,smoke-release}.sh`.
  Repo-owned: `scripts/release.conf`, `scripts/release-smoke-hook.sh`.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't
  rename it.

## Release

- From a clean, up-to-date `main`: `scripts/release.sh --dry-run`, then
  `scripts/release.sh --push` (pushes `main` and the tag).
- Tags are `YYYYMMDD-HHMMSS-<8hex>` (UTC committer time plus commit
  hash), not Cargo semver; `release.yml` fires only on that shape.
- Assets: `linux-{x86_64,aarch64}-musl`, `macos-{x86_64,aarch64}`, and
  `android-aarch64` archives, with checksums and attestations.
